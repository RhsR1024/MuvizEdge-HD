# 158 启动恢复计时与结果诊断

日期：2026-10-06。版本158 / 2.1.4.0-adaptive-zh16。

## 157 实测结论

10月6日导出日志保留四个启动会话：boot990在07:59:07.974播放后，于07:59:10.215取得非零后台FFT；boot991、992一直未恢复到各自关机；boot993在13:25:30.713进入Activity后才恢复访问，13:25:36.074取得非零后台FFT。三个失败会话中完整服务重建都完成了，但没有恢复后台采集资格。该样本不是整体失败率。

失败期间运行时授权及rawOp可允许，但实际record AppOp为ignored、进程importance为125；进入界面后实际访问变为允许。此关联不能证明ROM只能通过可见Activity解锁，也不能认定重试必然有效。早上成功会话未重建即可工作，唯一原因仍未确定。

boot993短暂的播放状态跳变曾把接近30秒的持续失败计时清零，推迟重建。158针对这一明确问题修正，不宣称已经解除ROM限制。

## 158 行为

- 在原有重建条件下，单次不超过2秒、累计不超过5秒的暂停保留此前有效失败时间；暂停时间不计入30秒门槛，暂停中不触发重建。长暂停及硬性条件变化仍重置计时。
- 仍仅Android11大屏且启用车机音频兼容时适用，每次启动或确认休眠唤醒最多一次完整服务重建；已有后台FFT则不再重建。普通音频恢复继续保留。
- STARTUP_RECREATE_OUTCOME区分等待、实际访问被忽略、访问拒绝或未知、无后台帧、播放暂停待验证、收到后台帧、进入Activity后才收到帧。后台帧可能全零，是否非零必须另看首帧记录，服务就绪不算成功。
- 结果与服务代次和唤醒周期绑定；新唤醒清除旧周期展示结果。进入界面后的恢复不能标成自动恢复。
- STARTUP_STAGE及导出快照增加targetSdk、电池优化豁免、音频模式、麦克风静音和公开API可见录音配置（含silenced）信息。明确processImportance / processPid；旧uidImportance字段仅兼容历史解析，它实际也是进程重要性。
- API30公开SDK不能读取完整UID麦克风能力，因此uidAggregateImportance和uidMicrophoneCapability明确记unknown_public_api30，不使用隐藏接口。录音配置受系统过滤，不可据空列表推断没有录音，也不是Visualizer可用证明。

无新增权限、不自动拉起Activity、不生成伪频谱；导航栏映射、手机显示与设置保留。日志不记录音频内容，总上限仍2MiB。
