## 工程来源和目标

从用户提供的 Muviz Edge APK 持续修改而来，保留其原始 smali、资源和原生库，以附加 Java 辅助层实现适配。本仓库已经包含此前修改后的完整状态，不需要重新寻找最初 APK 或执行旧目录的补丁脚本。

目标是一个 APK 同时适用于普通手机和横屏车机，提供中文、合理的字体 / 控件大小、随导航栏显隐调整的底部律动，以及可诊断的后台播放恢复。

主要设备场景：Android 11，2560 × 1600，物理 density 160；音乐由车机内安装的音乐 App 播放。150 日志可见 `com.wayfarer.music` 正在播放，其他媒体会话同时存在；不要用导出时单个会话状态推断整段历史。手机兼容场景包含 Android 13 / 小米 10 / HyperOS 1.0.7.0.TJBCNXM。

## 已处理和用户反馈

- 手机安装后黑屏曾与启动弹框有关；移除对应启动初始化后，用户反馈可以打开。保留 `MuvizEdgeApp.<clinit>` 的现状，不能恢复旧弹框。
- 大屏横屏、中文和界面缩放已加入，手机可保留系统显示大小。
- 扩大了大屏边距设置范围；后来进一步加入自动测量，不再要求用户为正常导航栏手动设置底部高度。
- 用户反馈导航栏避让已经有效，同时曾遇到播放恢复延迟、重启 / 唤醒后无律动、偶发只有上边没有下边。
- 148 加入启动恢复和持久诊断。最新收到的 148 日志显示：进程、启动接收器和前台服务确实启动了，后台 Visualizer 初始化返回错误 `-3`，进入应用界面后出现成功采集。因此不能把这份日志归结为“开机广播完全没收到”。

原始用户日志不随仓库发布。此处只保留定位结论，不保留个人时间线或设备日志全文。

## 149 相对 148 的具体变化

1. `PlaybackRecovery.repair()` 改为调用原始 `ib.e.f()`，包含原程序的 tunnel 音频兼容准备，然后设置 FFT 回调并启用采集。不要回退到直接 `new Visualizer(0)`，也不要在这里直接调用整个刷新循环而产生重复绘制任务。
2. `NavigationInsets.Watcher.refresh` 在已经启动但仍等待采集就绪时延后刷新，避免首个回调到来前又因显示条件不满足销毁 Surface，形成反复建立 / 销毁。
3. 新增 `CaptureDiagnostics`，在原始 `ib.e.e(boolean)` 上记录初始化开始、完成和异常；记录 AppOps 的录音模式、运行重要级、已有 Visualizer 和 tunnel 准备状态。
4. 版本号升为 149；其他资源、原生文件和原始方法保持 148 基线。

## 已验证与未知

149 已通过 377 项 JVM 逻辑检查；150 加入 43 项桌面策略检查，总计 420 项。校验器检查原始 7847 个类及类间调用、149 的 55 个辅助类（150 为 63 个）、5599 个未改动资源 / 原生 / 其他文件、资源 ID、签名及 zipalign。仓库迁移分别验证了原签名构建和全新目录自动开发签名构建，结果在 `verification/repository-build.json`、`verification/clean-checkout-build.json`；两次构建的非签名条目内容均与当前 149 成品一致。

150 曾在一次重启后连续 54 次后台恢复失败；151 已修复服务采集类型和默认授权模式。151 两次真正重启日志均有进入界面前的非零 FFT；覆盖安装后的会话仍受过后台限制。因此不能将所有历史错误归入最新启动，也不能声称所有入口均已修好。152 保持音频逻辑，只修改边距测量和日志导出，新增 39 项检查，总计 535 项；最新车机反馈和日志已支持导航适配改善，但 152 没有新增冷启动实测。153 只移除桌面快捷方式，尚待设备验证。

还有这些边界：

- `SERVICE_FOREGROUND` 不等于已取得音频；`CAPTURE_NATIVE_CONFIGURED` 不等于有非零频谱；`RENDER_DRAW` 不等于底边一定在可见区域。
- 进程不运行时无法写日志，不能仅凭没有日志断言系统没有唤醒事件。
- Android 15+ 禁止某些从开机启动的媒体前台服务，当前策略会等待实际界面启动。主要适配 / 实测目标仍为 Android 11 和 13。
- 系统或播放器不向 Visualizer 提供音频时，媒体会话存在也无法生成真实频谱。

## 建议下一步

1. 先按 `docs/BUILD.md` 完成干净编译，确认使用的签名能覆盖已装版本。
2. 在车机覆盖安装 153 后先打开主应用一次，确认只保留 Muviz Edge 主图标、“设置 / 息屏显示”快捷入口消失且应用内设置仍可打开。桌面可能保留旧固定快捷方式，见 `SHORTCUTS153.md`。保持使用情况访问和自动测量开启，继续验证全屏管理工具 / 系统权限页往返及导航栏重新出现时的避让。
3. 问题出现后进入“显示与语言 → 音频与悬浮状态”导出日志。打开界面可能恢复功能，因此应看导出文件里的历史事件，不能只看顶部当前快照。
4. 真正重启或休眠唤醒后，先不进入 Muviz Edge，直接播放并记录延迟。对比进入界面前后的 `CAPTURE_NATIVE_*`、AppOps、`serviceType`、`HEARTBEAT` 的回调年龄；type=130 但仍拒绝时调查 ROM 的后台权限限制。
5. 底边异常时同时检查 `NAVIGATION_RELAYOUT`、`NAVIGATION_WINDOW`、`OUTLINE_APPLIED`、`RENDER_DRAW`，先区分系统信号仍旧、没有绘制、窗口裁剪和底边映射错误。日志空洞现在导出为 LOG_GAP；不能把空洞附近缺失的事件当成从未发生。
