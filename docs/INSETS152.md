# 152：切换全屏后的导航栏重测

## 151 实测结论

新日志来自 Android 11 / 2560 × 1600 / 原生 density 160，包含多个历史会话，不能将旧版本错误算在最新一次启动上。151 覆盖安装后的会话仍有后台录音限制；其后真正重启的会话，服务类型为 130，早期两条原始采集错误后，仅一次后台恢复便取得音频。此后有持续非零 FFT，约半小时后才第一次进入 Muviz 的 HomeActivity。这次重启已验证无需先打开应用即可恢复；不能据此保证所有开机 / 覆盖安装入口都已无问题。

使用情况访问值为 check=3、raw=3、note=3、permission=0，即 MODE_DEFAULT + 系统授予 PACKAGE_USAGE_STATS。151 的默认模式回退已实际生效，HOME 和前台 Activity 均有有效记录。

图二是车机管理应用的全屏功能面板。日志中的相应包名 `com.yunpan.appmanage` 已正确识别为非 HOME。有一段从系统权限页返回该应用后，系统继续报告 navVisible=true / current.bottom=160，渲染器也确实使用 160；十几秒后才恢复隐藏信号。这与图片的悬空现象吻合，但图片没有可核对的精确时间，不能将其唯一对应到某一行。

同一应用还有约 70 ms 的 visible→hidden 跳变，151 会立即抬高边距，再等待隐藏防抖回落。上述证据支持系统导航栏状态迟滞和切换瞬间的可见信号干扰，没有证明渲染器收到 0 后仍保留了 160。

## 实现

1. `DesktopSupport` 发布新的前台包名 / Activity 后主动通知主线程测量，减少等待原 350 ms 轮询的时间。
2. `InsetRecheckPolicy` 为每个新的已确认前台组件安排有限的重测：立即、250 ms、1 s、3 s。新组件替换旧计划，同组件重复事件不重启计划，窗口卸载或自动模式关闭时取消。
3. 重测使用现有窗口参数调用 `WindowManager.updateViewLayout`，要求系统重新计算窗口状态，再读取 Insets。保持窗口大小 / flags，不主动移除 Surface 或重建音频。未新增常驻探测窗口。
4. 已经贴底且确认前台为非 HOME 时，对新的正导航栏高度要求稳定 200 ms；约 70 ms 的脉冲不会再抬高律动。持续可见的导航栏仍须避让，确认 HOME、未知前台、键盘 / 侧栏、初次可见高度保持原规则。
5. 隐藏仍采用 250 ms 防抖，但采样会按剩余时间安排，不再总等到下一个 350 ms 周期。

这些操作让系统主动重算，而不把所有非 HOME 应用都假定为全屏。若重测后厂商仍持续提供错误的可见信号，152 不能凭 UsageEvents 单独证明栏已隐藏；需看重测日志和图片，进一步寻找独立可靠信号。不能通过永久固定 0 或 160 掩盖这个限制。

## 新日志与损坏记录

- `NAVIGATION_FOREGROUND`：触发重测的前台组件、是否新鲜和 HOME 判定。
- `NAVIGATION_RELAYOUT` / `NAVIGATION_RELAYOUT_FAILED`：主动重新布局的时间、组件、当前采用高度及错误。
- `NAVIGATION_RECHECK_RESULT`：请求后约 100 ms 观测到的 Insets 和采用高度，即使数值没有改变也会记录；`SYSTEM_IMMERSIVE_POLICY`：系统公开的 policy_control 值（可能为空 / 不可读），只作诊断，不据此强制贴底。
- `NAVIGATION_WINDOW` 增加同一条记录中的前台证据和是否启用正高度防抖；结合 `OUTLINE_APPLIED`、`RENDER_DRAW` 追踪最终结果。
- 本次原始日志中有两段 NUL 字节，分别在重启会话边界附近。原因未证实，不能认定为日志代码主动写入。152 导出时用 `LOG_GAP nullBytes=...` 标记空洞，避免文本工具将整份日志当二进制而跳过新启动记录。原文件保留，已经丢失的内容不能恢复。
- 保持 2 MiB 滚动 / 导出上限；重测有次数限制，音频不新增逐帧日志。

后续实测更新（2026-10-02）：用户反馈 152 稳定性明显改善，新日志的隐藏信号处理、渲染边距和正常播放采样与此一致。覆盖安装后后台采集限制仍出现；该日志中的真正重启发生在升级前的 151。详细结论与 153 修改范围见 `SHORTCUTS153.md`，不能将此反馈视为所有场景均通过。

API 校验器原来只遍历类的父类，漏掉 WindowManager→ViewManager 接口继承。152 补充接口遍历，并用 8 项 API 解析检查核实继承、构造器和缺失 API；未跳过实际 DEX 方法校验。

车机重点复测：桌面 / 应用列表 ↔ 全屏管理工具，工具内部页面切换、进入系统权限页再返回；观察立即、1 秒、3 秒以及持续停留时的底边。实际导航栏重新出现时必须仍自动避让。若长时间悬空，导出 152 日志并记录大致时间，比较每次主动重测后系统信号是否变化。手机默认不开启桌面兼容，应保持原导航策略。
