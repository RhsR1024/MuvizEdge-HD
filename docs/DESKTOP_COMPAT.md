# 150：返回车机桌面后避让控制栏

## 149 日志与照片的结论

用户照片中的车机桌面底部控制栏可见，律动却贴着物理屏幕底部。相应时间段日志仍为 `navVisible=false`、`current.bottom=0`，而 `stable.bottom=160`，随后 `OUTLINE_APPLIED` 和 `RENDER_DRAW` 都使用底边 0。这说明该场景中的系统导航栏可见性不足以表示桌面控制栏是否可见。

不能把导出文件顶部“采用高度 160、最近实际边距 0”直接当作刷新失败：打开本应用会暂挂悬浮层，此时最近应用到渲染器的边距是历史值。150 已更正此处文案。

音频方面，149 日志后段持续收到真实非零 FFT；前段仍出现两轮恢复失败，当时录音权限已授予，但 AppOps 有效模式为 1（ignored）、原始模式为 0。后续有效模式变为 0，第三次恢复成功。此证据支持后台录音访问限制参与了失败，但不能证明本次桌面适配修改解决了厂商音频权限问题。

## 使用方法

1. 使用原签名覆盖安装 150，不需卸载 149。
2. 在“显示与语言”保持“底部自动测量”和“车机桌面兼容”开启。
3. 点击“开启使用情况访问 · 用于识别车机桌面”，在系统页面允许 Muviz Edge 访问，再返回应用。
4. 从全屏音乐软件返回桌面 / 桌面应用列表，观察律动是否移到控制栏上方；重新进入全屏播放器，应恢复贴底。

无需手工设置底部高度。使用情况访问是已有 Manifest 权限，150 增加可见入口与用途说明，授权仍由用户在系统中完成。没有授权时保留原系统导航栏策略，不会声称已启用桌面识别。

## 实现与回退

- `DesktopSupport` 通过 HOME Intent 找出桌面包名，使用已授权的 UsageEvents 判断实际前台 Activity，而不是根据媒体会话判断前台。
- 后台线程最多每 500 ms 发起一次查询（受原 350 ms 采样周期影响）；初次 / 长间隔后读取最近 5 分钟，后续查询只读增量并重叠 2 秒。
- `ForegroundPolicy` 处理 resume / pause / stop，并忽略旧时间事件；不同 Activity 的迟到 pause 不清除新的前台 Activity。
- 查询结果超过 3 秒或查询失败时不使用桌面覆盖。没有 HOME 包名、没有明确前台或权限被撤销时退回系统策略。
- 桌面确认后，只对系统隐藏 / 未知的底边信号补充判断；高度依次取系统稳定导航栏高度、同一屏幕几何下以前测得的高度、系统原生导航栏尺寸。
- 保持可见导航栏的实际测量优先，不把侧面导航栏或键盘区域当作底部控制栏；不叠加用户旧边距，不修改手动保存值。
- 离开桌面后继续使用原隐藏防抖，正常进入全屏时归零。手机默认不开启桌面兼容。

这些判断依赖厂商正确提供 UsageEvents 和 HOME 信息。由另一个非 HOME 包实现的特殊应用列表暂不强行视为桌面；若仍有问题，应根据新增诊断定位其包名和 Activity。不能为规避不确定性而对所有播放场景固定保留 160 px。

## 新日志

| 事件 | 用途 |
| --- | --- |
| `DESKTOP_ACCESS` | 未授权 / 功能关闭 |
| `DESKTOP_PACKAGES` | 系统返回的 HOME 应用包名 |
| `DESKTOP_FOREGROUND` | 前台包名、Activity、是否桌面、事件时间和判断原因 |
| `DESKTOP_QUERY_FAILED` | 查询异常 / 数据不可用 |
| `DESKTOP_INSET_FAILED` | 桌面边距补充过程异常 |
| `NAVIGATION_WINDOW` 的 `source=桌面兼容自动避让` | 已使用桌面补充判断，原始 navVisible 仍保留以便对比 |

状态页保留最近一次本应用以外的前台记录，便于进入应用导出后查看。日志包含包名 / Activity 名，不读取屏幕、歌曲正文或音频内容。原始用户日志与照片不提交到仓库。

420 项 JVM 检查包含 43 项新增桌面事件 / 权限 / 高度策略检查；完整静态 / 签名构建结果见 `verification/desktop150-build.json`。150 的目标车机实测仍需用户复测，不把逻辑测试当作 ROM 实测。
